Спецификация боя со Spamton NEO (Deltarune, Chapter 2) для клона.
**v3** — обновлено по правкам после Этапов 0 и 2. Зафиксированные
решения помечены **[РЕШЕНО]**, ещё открытые — **[ПРОВЕРИТЬ]**. См.
низ файла (§ «Прогресс по этапам») за текущим статусом реализации.

Источники (веб-поиск; прямой доступ к вики из этой песочницы

## 0. Ключевое решение по концовкам — [РЕШЕНО]

**Вариант A принят, с уточнением:** кнопка **SPARE присутствует в
меню у всех трёх персонажей всегда**, как в любом бою Deltarune — но
на Spamton NEO она **никогда не срабатывает**: выбор SPARE выводит
системную реплику о неудаче (текст — позже, см. диалоги) и ход
считается потраченным впустую (без урона/эффекта, аналог "пропуска").

Единственный настоящий путь к мирной победе — **Mercy% через ACT**:
`Snap` / `Snap All` у Kris, `S-Action`/`R-Action` у Susie/Ralsei (см.
§3). При Mercy% = 100 — скриптовая сцена "падает без нитей" →
`VictoryWires`.

## 1. Структура боя (машина состояний верхнего уровня)

```
Boot
 └─ StartMenu ("Начать игру" / "Начать сразу с боя")
Intro
 ├─ PhoneCallGag        (телефон, гэг "это тебе звонят")
 ├─ NeoDeclaration      ("Power of NEO", "Big Shot" спич)
 └─ [пропуск: удержание C 1 сек ИЛИ пункт стартового меню]
BattleLoop
 ├─ PartyMenu                 (по очереди Kris → Susie → Ralsei выбирают действие)
 │   ├─ FIGHT   → откладывается, резолвится позже вместе с остальными FIGHT
 │   ├─ ACT/MAGIC → подменю (см. §3, разное у каждого персонажа)
 │   ├─ ITEM    → подменю предметов
 │   ├─ DEFEND  → +TP, снижение входящего урона в этот ход
 │   └─ SPARE   → на NEO всегда "неудача" (см. §0)
 ├─ ResolveNonFight     [РЕШЕНО] — сначала ITEM/ACT/MAGIC/DEFEND/SPARE
 │                       всех, кто их выбрал, по порядку Kris→Susie→Ralsei
 ├─ ResolveFight        [РЕШЕНО] — затем FIGHT: полоски тайминга ВСЕХ,
 │                       кто выбрал FIGHT, идут ОДНОВРЕМЕННО на экране
 │                       (как в настоящем Deltarune), подтверждение —
 │                       по очереди, но движение полос — параллельно
 ├─ EnemyAttack          (жёлтая душа, атака по номеру хода — см. §5)
 ├─ CheckWinLose
 │   ├─ HP NEO ≤ 0        → VictoryFight
 │   ├─ Mercy% = 100      → VictoryWires
 │   └─ HP всей партии = 0 → GameOver
 └─ иначе → назад в PartyMenu (номер хода +1)
Victory (эпилог + возврат в StartMenu)
GameOver (эпилог + Retry)
```

**[ПРОВЕРИТЬ]** (не критично, можно поправить позже без переделки
архитектуры): ходит ли партия каждый раунд заново по всем троим, или
возможен пропуск персонажа. Пока считаем — каждый раунд действие
выбирают все трое.

## 2. Статы

### Spamton NEO
- HP: **4809**
- ATK: **13**
- DEF: **0** (обычный маршрут). DEF уменьшается на 3 каждый ход
  после хода №16, до минимума −12.
- **[РЕШЕНО]** Weird Route (DEF −27, PipisExplosion-эксклюзив) —
  **вне scope**, не реализуем вообще.
- Атаки выбираются **по номеру хода**, не по HP% — см. §5. Порог
  DEF (ход 16) — единственная привязка к номеру хода, которая уже
  подтверждена источниками; отдельные HP%-пороги фаз атак **больше
  не нужны**, т.к. атаки теперь идут по фиксированной
  последовательности.

### Партия (Kris / Susie / Ralsei) — [РЕШЕНО, дефолт]
Точных цифр вы не прислали — фиксирую предложенные ранее круглые
числа как рабочий дефолт. Значения лежат в одном конфиг-файле
(`src/config/party.ts`), поменять — одна правка, без логики:
- Kris HP: **90**
- Susie HP: **112**
- Ralsei HP: **80**
- Общий TP: шкала **0–100**, +TP за DEFEND и за получение урона
  (**[ПРОВЕРИТЬ]** точный прирост — ставлю плейсхолдер в конфиге).

## 3. Меню боя — [РЕШЕНО]

У каждого персонажа — свой набор пунктов. **ACT и MAGIC — разные
пункты**, не один: у Kris нет MAGIC, у Susie/Ralsei нет ACT.

| Пункт | Kris | Susie | Ralsei |
|---|---|---|---|
| FIGHT | ✔ (Wushuang Blade) | ✔ (Axe, урон выше) | ✔ (Scarf, урон слабее) — **[РЕШЕНО]** |
| ACT | Check, Snap, SnapAll | — | — |
| MAGIC (тратит TP) | — | Rude Buster, UltimateHeal, S-Action | Heal Prayer, Pacify, R-Action |
| ITEM | ✔ | ✔ | ✔ |
| DEFEND | ✔ | ✔ | ✔ |
| SPARE | ✔ (всегда неудача на NEO) | ✔ (всегда неудача) | ✔ (всегда неудача) |

Пояснения:
- **Check** — HP%/ATK/DEF NEO + строка флейвор-текста.
- **Snap** — перерезать одну нить, основной источник Mercy% для Kris.
- **SnapAll** — **[РЕШЕНО]** условие разблокировки настраивается в
  `src/config/party.ts` → `SNAP_ALL_CONFIG` (`unlockMode: 'always' |
  'afterManualSnaps' | 'mercyThreshold'` + `unlockValue`). По
  умолчанию `'always'`. Также настраивается
  `consumesWholePartyTurn` (по умолчанию `true`): SnapAll тратит ход
  ВСЕХ троих — Susie и Ralsei в этот раунд не действуют (это
  проверяется/применяется в Stage 4, конфиг уже готов).
- **S-Action / R-Action** — теперь внутри MAGIC (тратят TP), а не в
  ACT. Каждое поднимает Mercy% на меньшую величину, чем Snap.
- **Rude Buster / UltimateHeal / Heal Prayer / Pacify** — боевые/
  лечебные заклинания, стандартная механика Deltarune (Rude Buster —
  урон по врагу, UltimateHeal/Heal Prayer — лечение партии, Pacify —
  **[ПРОВЕРИТЬ]** предполагаю "снижает урон входящей атаки/накладывает
  защитный эффект", как в оригинале Ralsei).
- Числа: урон Rude Buster, лечение HealPrayer/UltimateHeal, TP-цена
  каждого — всё в `src/config/magic.ts`, плейсхолдеры до плейтеста.

FIGHT-полоски — **[РЕШЕНО]**: если FIGHT выбрали, например, Kris и
Susie, обе полоски отображаются и двигаются **одновременно**, игрок
подтверждает каждую по очереди (стандартная реализация: активная
полоса управляется текущим инпутом, уже подтверждённые — замирают
на месте попадания и показывают результат, ещё не начатые — не
показываются или показываются идущими с той же начальной фазы, чтобы
визуально "ехали вместе", как в настоящем Deltarune).

## 4. Механика души

### Красная душа (свой ход)
Во время выбора действий в меню — отдельной души на экране нет.

### Жёлтая душа (ход врага) — фирменная механика этого боя
- Всегда жёлтая (кроме cart-атак, см. ниже).
- Управление — **[РЕШЕНО]**:
  - Стрелки/WASD — движение по battle box.
  - **Z/Enter** — выстрел вверх; удержание — заряд **Big Shot**.
  - **X** — отмена/назад (в меню); в бою — не используется отдельным
    действием во время атаки (кроме уже описанного "вывести реплику
    целиком" в диалогах). Debug-переходы Этапа 2 (X → Victory/GameOver)
    убраны с X и перенесены на **F1 (Victory) / F2 (GameOver)**,
    работают глобально из любого состояния и только при
    `import.meta.env.DEV` (вырезаются из прод-сборки, проверено —
    строка `'F1'` отсутствует в `dist/`).
  - **Shift** — **не реализуем**, зарезервирована клавиша, по
    умолчанию ничего не делает. Никакого "медленного шага".
  - **C** — открыть меню / удержание 1 сек — пропуск интро.
- Хитбокс души меньше спрайта. Кадры неуязвимости с миганием после
  попадания — стандартно.
- Цель — сбивать снаряды выстрелами; несбитые могут "размножаться"
  (Pipis → 4 мини-головы и т.п.).
- Big Shot также отталкивает вражеские объекты (PhoneHead).

### "Cart"/lane-режим
Часть атак (`LaneDodge`, `MailTrucks`) переключают душу в режим
выбора полосы вместо свободного движения — dodge-only, без стрельбы,
**[ПРОВЕРИТЬ]** число полос — ставлю 4 по умолчанию.

### Коробка боя
Размер/форма меняются под атаку. Точные размеры — на глаз при
реализации каждой атаки, задаются в конфиге атаки, а не хардкодом.

## 5. Атаки — теперь по фиксированной последовательности ходов

**[РЕШЕНО]** Атаки выбираются **по номеру хода**, не по % HP.
Последовательность — один типизированный массив в
`src/attacks/sequence.ts`:

```ts
export const ATTACK_SEQUENCE: AttackId[] = [
  // ход 1, 2, 3, ... — заполняется по видео оригинального боя.
  // Пока пусто/пример — актуальный порядок пришлёте вы.
  'PhoneHead',
  'PipisSwarm',
  'HeadRush',
  'LaneDodge',
  'MailTrucks',
  // ...
];
```

**[РЕШЕНО]** Поведение при выходе за пределы массива настраивается в
`src/config/attacks.ts` → `ATTACK_SEQUENCE_CONFIG.loopMode`:
`'loopAll'` (по умолчанию — зациклить весь массив с начала) или
`'repeatLast'` (повторять последний элемент). Реализовано и
проверено в `src/attacks/sequence.ts`.

### Модули атак (рабочие имена, без изменений по описанию паттернов)

| # | Имя | Тип | Паттерн |
|---|---|---|---|
| 1 | `PhoneHead` | box | Голова с телефонами-руками ползёт к игроку, стреляет по контакту; Big Shot отталкивает. |
| 2 | `LaneDodge` | cart | По одной из ~4 полос — голова (малый урон) / бомба (большой урон) / письмо (без урона); нужно встать в безопасную полосу. |
| 3 | `MailTrucks` | cart | Вариант LaneDodge: грузовики с башнями писем/головами/бомбами. |
| 4 | `PipisSwarm` | box | "Pipis" летит вверх; не сбитый — лопается на 4 мини-головы. |
| 5 | `HeadRush` | box (полосы) | 4 копии головы по одной на полосу; со 2-го повтора — с нескольких направлений + крупные снаряды из рук-пушек. |
| 6 | `FreeTurnCall` | — | **[ПРОВЕРИТЬ], реализуется последней/низкий приоритет.** Комедийная вставка-звонок, без урона игроку. |
| 7 | `PowerOfNeo` | особый (чёрный фон) | Экран гаснет, крупный план NEO, "вдох", крупные снаряды-лицо, финальный снаряд во весь бокс. |

`PipisExplosion` (Weird Route) — **[РЕШЕНО] исключена**, не
реализуем.

### Числовые параметры — [РЕШЕНО] всё в конфиг
Каждая атака получает свой объект конфигурации в
`src/config/attacks/<AttackId>.ts` (или один общий
`src/config/attacks.ts` со вложенными объектами — решим на этапе
реализации атак, принцип одинаковый): скорости снарядов, интервалы
спавна, длительность атаки, размер battle box — **никаких магических
чисел внутри логики атаки**, только чтение из конфига. Это позволит
вам подкручивать тайминги без прикосновения к коду атаки.

### Известный баг оригинала — не переносим
Клавиатурный эксплойт "бесконечный Big Shot без разрядки" +
"angry"-состояние (ATK +0.5 за читерский выстрел, кап 26) — осознанно
не реализуем, это баг оригинала, а не механика.

## 6. Победа / поражение / пощада — [РЕШЕНО]

- **Поражение:** суммарный HP партии = 0 → GameOver, кнопка "заново"
  (рестарт боя).
- **Победа через FIGHT:** HP NEO ≤ 0 → VictoryFight.
- **Победа через ACT:** Mercy% = 100 → сцена "падает без нитей" →
  VictoryWires (отдельный текст/подача от VictoryFight).
- **SPARE:** доступен всегда всем, на NEO **всегда проваливается**
  (см. §0) — никогда не завершает бой.

1. `PhoneCallGag` — 2–4 короткие реплики.
2. `NeoDeclaration` — "Power of NEO" / "Big Shot" спич.
3. Посимвольный вывод + звук на символ; **Z** — дальше (или
